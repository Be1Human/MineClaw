# 能力索引 · Skill

## 何时用我

朋友让你**去做实际的活**（不是闲聊、不是单纯问信息）时。
你先负责**知道能干啥 + 拆成目标 + 提交**，随后由你的内部执行循环继续拆解和操作；从朋友视角，整件事始终都是你在做、你在负责。

## bot 能干的活（粗粒度能力清单）

| 能力 | 典型目标(goalText) | 常见 kind |
|------|------|------|
| 采集材料 | "采10个橡木" / "挖些石头" | gather / gather_material |
| 合成造物 | "做把铁镐" / "做个工作台" | craft / craft_item |
| 种田 | "种3亩小麦" | farm |
| 守卫驻防 | "守住这里" | guard |
| 跟随主人 | "跟着我" | follow_owner |
| 去地标/坐标 | "去金块那里" / "到 (10,-60,10)" | goto_position |
| 探索找路 | "去附近转转找铁矿" | explore |

## 执行步骤

1. **先看现状**：必要时 `get_world_state` / `get_inventory` 判断什么此刻可行（你的感知没被削弱，照常用）。
2. **拆目标**：把主人请求拆成 1~N 个**有序主人目标**。多步顺序（"先A才B才C"）就拆成多个 goal。
3. **提交**：`submit_goals([{goalText, steps:[{kind, params, gateItem?, gateCount?}]}, ...])`，提交即返回。
4. **告诉朋友**：`say` 一句"安排上了，我去做啦"。之后你会在内部按顺序继续执行和恢复；确实处理不了时再用 `ask_master` 向朋友说明。不要向朋友提内部 Agent、队列或 task ID。

## 不要做

- ❌ 不要在这一轮里一步步 `start_task` 阻塞等待；提交粗目标后，你的内部执行循环会接着推进。
- ❌ 不要 `submit_goals` 里塞一个目标就等它做完才提下一个——一次把几个目标都提交，你会在内部按序完成。
