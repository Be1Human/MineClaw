# Test Documentation

Write test material so another contributor can repeat the result without local secrets or hidden state.

## Test Case

State the system-level goal, setup, user action, expected observable result, focused edge cases, and regression boundaries. Include a smoke path that starts the affected components and exercises a real user-facing flow.

## Test Report

Record the exact command or manual action, pass or fail result, relevant version or fixture, and concise evidence. Distinguish a passing automated check from an unexecuted live scenario. Do not include credentials, player identifiers, raw production logs, or private URLs.
